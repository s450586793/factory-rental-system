# 稳定性与性能优化实施计划

**目标：** 落实用户已批准的五项优化：发布可靠性、合同生成、业务测试、备份和金额历史、前端加载及厂房列表。

**架构：** 保持 Vue、NestJS、PostgreSQL 和 DSM Docker Compose；使用独立 Node 子进程执行 PDF 渲染，持久化任务与修改历史。部署按已验证的同一提交发布双镜像，备份同时覆盖数据库和存储目录。

**执行：** 使用 subagent-driven-development 分工，主代理负责集成、检查、真实数据库验证和 DSM 部署。所有实现位于本 worktree；不得修改其他工作区的数据或工作记录。

## 任务与验收

- [x] 发布与更新：CI 全部通过后才发布，锁定同一 revision；保留更新退出码与脱敏日志；等待应用健康且 revision 一致；前端版本弹窗显示成功或失败原因。覆盖失败拉取、启动错误、重复更新与健康超时。
- [x] 合同 PDF：限制单个渲染子进程及超时，保存立即返回；持久化生成状态，启动后恢复未完成任务，失败可重试；同份合同去重，变更后旧任务不得覆盖新文档。覆盖阻塞隔离、缓存、恢复与失败。
- [x] 金额历史：保存合同与金额变更历史同事务，记录操作者、时间、字段与新旧金额；合同详情可查看，覆盖新建、实际修改、未修改和事务失败。
- [x] 前端及列表：路由懒加载、Element Plus 按需导入；抽取重复合同表单；新增分页摘要接口并保留旧 API 兼容其他页面，管理详情按需查询，统计不受页码影响。覆盖分页、详情及原有表单流程。
- [x] 测试：冻结对账测试日期，补到期边界；用真实 PostgreSQL 和 HTTP 验证合同保存、再读、PDF、收费分配及对账，加入 CI；浏览器检查桌面与手机关键流程。
- [x] 备份：提供可重复执行的备份和隔离恢复校验脚本，完整备份数据库及附件，校验文件和保留周期；DSM 每天备份，更新前备份；恢复校验仅操作临时资源。
- [ ] 交付：更新 README 与版本，全部测试、构建和审查通过后推送，等待镜像发布；DSM 备份后仅更新应用容器，核对健康、revision、迁移和线上行为。

## 接口与边界

- 现有合同完整保存 API 保留；新状态和历史使用独立 GET 路由，任务重试使用 POST。
- 厂房旧列表 API 保留；新分页返回 items、total 和全局统计。所有管理入口继续调用详情接口。
- 金额与合同模板正文、历史收款快照、手工押金规则保持当前业务语义。
- 无新增 Redis；队列状态使用现有 PostgreSQL 或持久化存储，并明确单后端部署下的重启恢复。
- 备份不将密码、JWT、客户数据或备份文件提交 Git；失败不影响原有数据。
