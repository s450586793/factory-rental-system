# 收款凭证拖拽上传设计

## 目标

将房租收费和押金记录中现有的原生文件选择框升级为统一的图片拖拽上传控件，并为水电收费补齐收款凭证的上传、补传、移除和预览能力。

上传仍沿用现有文件接口和 `payment-voucher` 文件分类，只支持 JPG、PNG、WebP 图片，每条业务记录最多关联 10 张。房租和押金的保存流程及后端附件结构保持不变；水电收费新增附件关联关系，不改变已有记录的金额、抄表或缴费状态口径。

## 共用拖拽组件

新增 `PaymentVoucherUpload` 组件，由房租收费、押金记录和水电收费共同使用。组件负责：

- 点击上传区域时打开系统文件选择器；
- 接收从桌面或文件管理器拖入的多张图片；
- 拖入期间使用现有绿色品牌色显示明确的边框和背景状态；
- 展示已有凭证和本次待上传图片的原始文件名；
- 支持分别移除已有凭证和待上传图片；
- 显示当前已关联和待上传图片总数；
- 支持键盘聚焦，并可通过 Enter 或空格键打开文件选择器；
- 在禁用状态下阻止选择、拖拽和移除操作。

组件接收已有文件列表和待上传 `File[]`，通过事件更新待上传列表并通知父页面移除已有文件。文件选择和拖拽统一调用现有 `appendPaymentVoucherImages`，确保类型和数量校验只有一份实现。校验失败时调用现有消息提示，且不清空已经选择的文件。

控件采用紧凑的全宽虚线边框、6px 圆角和清晰焦点样式，不嵌套卡片，不增加装饰性图形。移动端保持完整宽度和至少 44px 的可点击区域，文件名过长时允许换行或省略，不能撑破弹窗。

## 房租收费与押金记录

房租收费和押金记录表单删除当前可见的原生 `<input type="file">`，改用共用拖拽组件。现有状态继续由页面持有：

- 打开新增表单时，已有文件和待上传文件都为空；
- 打开编辑表单时，已有文件取当前记录的 `attachmentFiles`，待上传文件为空；
- 保存时先上传待上传图片，再将已有文件 ID 和新文件 ID 一并提交；
- 移除已有图片只更新本次表单状态，用户点击保存后才更新业务记录；
- 保存失败时保留表单和已选图片，允许用户重试。

房租和押金列表中的凭证数量及预览入口保持不变。此次不修改对应后端 DTO、entity 或数据库表。

## 水电收费交互

水电收费在实际收款步骤管理凭证，不在新增抄表收费记录时提前要求凭证。

点击未缴费记录的“标记已缴费”后打开收款弹窗，包含：

- 收款日期，默认当天；
- 付款方式，默认“转账”；
- 共用凭证拖拽组件；
- 取消和确认收款操作。

确认时先上传待上传图片，再调用水电收费 `pay` 接口提交日期、付款方式和全部凭证 ID。上传或保存失败时弹窗保持打开并显示中文错误，不将记录提前标记为已缴费。

水电收费列表新增“凭证”列。存在凭证时显示图片数量并可打开现有 `PaymentVoucherPreviewDialog`；没有凭证时显示 `--`。已缴费记录提供“管理凭证”操作，打开同一收款弹窗并回填收款日期、付款方式和已有凭证，支持补传、移除和预览。未缴费记录只能通过“标记已缴费”进入该弹窗。

历史已缴费水电记录默认没有凭证，但可通过“管理凭证”补传。历史未缴费记录不受影响。

## 水电收费后端与数据库

在 `UtilityChargeRecord` 上新增与 `StoredFile` 的 eager `ManyToMany` 关系，属性名为 `attachmentFiles`。新增 migration 创建 `utility_charge_record_attachment_files` 关联表，主键由 `utilityChargeRecordId` 和 `fileId` 组成，并分别建立外键和索引：

- 删除水电收费记录时级联删除关联行；
- 删除存储文件时级联删除关联行；
- migration 不修改现有水电收费记录，旧记录读取时附件列表为空；
- down migration 仅删除新增关联表。

`MarkUtilityRecordPaidDto` 新增可选 `attachmentFileIds`，使用与房租、押金相同的数组最大 10 项、唯一 UUID 校验。`UtilitiesModule` 引入 `FilesModule`，`UtilitiesService.markAsPaid` 通过 `FilesService.resolvePaymentVoucherFiles` 校验并解析文件，然后保存到 `attachmentFiles`。

为兼容旧客户端，`attachmentFileIds` 未传入时保留该记录现有的附件关系；显式传入空数组时清空附件。这样“标记已缴费”和“管理凭证”可以复用同一接口，也不会因只更新日期或方式而意外丢失凭证。

水电收费列表、详情和 `pay` 接口响应都返回 `attachmentFiles`。前端 `UtilityChargeRecord` 类型同步增加该字段，不暴露存储路径以外的新内部信息。

## 文件上传与一致性

三个页面继续先调用文件上传接口保存图片，再提交业务记录关联 ID。后端文件接口仍负责 MIME 类型校验，业务 service 再次校验文件存在、分类正确、图片格式正确、数量不超过 10 张且 ID 不重复。

如果图片上传成功但业务记录保存失败，文件会暂时作为未关联文件保留，这与现有房租和押金行为一致，本次不引入文件事务或自动清理任务。前端保留已选择文件以便重试，但再次重试时只上传当前仍为本地 `File` 的项目。

## 错误与边界处理

- 拖入非 JPG、PNG、WebP 文件时拒绝本批文件并提示“收款凭证仅支持 JPG、PNG 或 WebP 图片”；
- 已有和待上传图片合计超过 10 张时拒绝本批文件，并保留原有列表；
- 空拖拽、浏览器未提供文件或拖入文本时不产生状态变化；
- 同一次选择中的文件按用户提供的顺序追加；
- 水电收费记录不存在时返回现有“水电收费记录不存在”错误；
- 凭证 ID 不存在、重复、分类错误或不是支持的图片时，由现有文件 service 返回明确的业务错误；
- 管理历史水电凭证时，如果上传或保存失败，不改变原有凭证关联；
- 已有凭证文件下载失败时，预览组件保留文件名和新窗口入口，列表金额与缴费状态不受影响；
- 禁用状态、提交中状态和查看模式不能重复触发上传或保存。

## 测试与验收

前端测试覆盖：

- 点击拖拽区域触发隐藏文件选择器；
- 选择多张图片和拖入多张图片产生相同的待上传列表；
- 拖入期间正确切换视觉状态；
- 移除已有凭证和待上传图片分别发出正确事件；
- 非图片、超过 10 张和空拖拽不破坏现有选择；
- 房租和押金表单使用共用组件并维持原有保存 payload；
- 水电“标记已缴费”上传文件后提交日期、方式和凭证 ID；
- 已缴费历史记录可回填、补传、移除和预览凭证；
- 防止提交中重复点击导致重复上传或重复标记缴费。

后端测试覆盖：

- 水电 `pay` 接口关联合法凭证；
- 未传 `attachmentFileIds` 时保留已有凭证，传空数组时清空；
- 非法、重复、超量或不存在的凭证由文件 service 拒绝；
- migration 正向创建关联表、外键和索引，回滚删除关联表；
- 历史无凭证记录返回空附件列表；
- 水电收费列表和详情返回附件信息。
