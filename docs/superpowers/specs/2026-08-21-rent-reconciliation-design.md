# 房租对账设计

## 目标

新增独立的“房租对账”功能，帮助出租方按租户核对历年合同应收和实际收款。页面既能查看租户累计总账，也能展开到每一份合同租期和每一笔实付记录，并支持打印及下载 PDF 对账单。

本功能只汇总现有合同、房租收费、付款附件和收据数据，不增加应收账单表，也不改变现有房租收费流程。

## 对账口径

系统按合同中的 `tenantName` 归并租户。归并前去除名称首尾空格，名称完全一致的合同视为同一租户；名称不同的合同不自动合并，避免把不同主体误认为同一租户。

每份合同形成一个对账期间：

- 期间起止日期取合同的 `startDate` 和 `endDate`；
- 应收金额直接取合同的 `annualRent`，不按合同天数折算；
- 实收金额为该合同下全部有效房租收费记录的金额合计；
- 结欠金额为 `max(应收金额 - 实收金额, 0)`；
- 结余金额为 `max(实收金额 - 应收金额, 0)`。

租户累计总账为该租户全部纳入筛选范围的合同期间汇总：

- 累计应收为各期间应收之和；
- 累计实收为各期间实收之和；
- 当前结欠和当前结余按累计应收、累计实收重新计算，不将某一期的超收固定抵扣到具体后续合同；
- 状态分为“欠款”“已结清”“有结余”。

房租收费记录已经绑定 `contractId`，因此每笔实付只进入所属合同期间，不按付款日期推断归属。软删除的收费记录不参与统计。

## 页面入口与总账列表

左侧导航新增独立菜单“房租对账”，路由为 `/rent-reconciliation`。现有“房租收费”继续用于新增和管理收费流水，两个页面职责分开。

总账列表一行对应一个租户，显示：

- 租户名称；
- 合同期间数量；
- 累计应收；
- 累计实收；
- 当前结欠；
- 当前结余；
- 最后付款日期；
- 对账状态。

页面支持按租户名称、合同年度和对账状态筛选。合同年度筛选以合同期间与所选自然年存在交集为准；筛选后，汇总金额只计算筛选范围内的合同和对应付款。默认显示全部年度和全部状态。

金额统一保留两位小数。结欠为零时不显示欠款警示；结余为零时显示 `-`，避免把正常结清误解为超收。

## 租户对账详情

点击总账列表中的租户进入详情视图。顶部显示租户名称、筛选范围内的累计应收、累计实收、当前结欠和当前结余。

下方按合同开始日期倒序显示合同期间。每个期间显示房源、租期、应收、实收、结欠、结余和状态，并可展开实付明细。每笔实付明细显示：

- 付款日期；
- 金额；
- 收款方式；
- 备注；
- 付款附件；
- 有效收据。

付款附件沿用现有图片预览能力。有效收据可直接预览；作废收据不作为有效收据入口显示。没有实付记录的合同期间显示明确空状态，仍保留完整应收和结欠金额。

## 后端接口与数据流

新增独立的房租对账模块和只读接口，后端负责查询合同、有效房租收费记录及其有效收据，并完成全部金额汇总。接口返回租户汇总、合同期间汇总和付款明细所需的稳定 DTO，前端不重复实现财务计算。

列表接口支持租户关键词、合同年度和状态筛选。详情接口使用 URL 编码后的规范化租户名称定位同名合同，并接受相同的年度筛选。接口应复用现有鉴权、文件访问和收据预览方式，不返回文件系统路径或内部异常信息。

为避免 SQL `numeric`、JavaScript 浮点数和 PDF 输出之间产生分差，金额计算以“分”为单位汇总，响应时再转换为两位小数金额。

第一版数据量较小，可由后端一次查询相关合同、付款和收据后在服务层归并。接口必须避免逐租户或逐付款查询造成 N+1 查询；后续数据量增长时可以在不改变响应 DTO 的情况下替换为数据库聚合。

## 打印与 PDF

租户详情提供“打印”和“下载 PDF”两个操作。输出范围跟随当前合同年度筛选，内容包括：

- 标题“房租对账单”；
- 租户名称和生成日期；
- 累计应收、累计实收、当前结欠和当前结余；
- 各合同期间的房源、租期和金额汇总；
- 各期间的逐笔实付日期、金额、方式、备注和有效收据编号。

付款图片不嵌入 PDF 正文，避免文件过大；页面仍可预览原附件。打印和 PDF 使用同一份后端汇总结果及同一套对账内容，确保数字一致。PDF 文件名为 `房租对账单_租户名称_YYYY-MM-DD.pdf`，并对文件名中的非法字符进行清理。

PDF 生成失败时页面保留当前对账数据并提示重新下载，不影响查询和打印。租户没有符合筛选条件的合同时禁用打印与下载操作。

## 错误与边界处理

- 同一合同没有付款时，实收为零，结欠等于应收；
- 部分付款时，展示所有实付并计算剩余结欠；
- 超额付款时，结欠为零并明确显示结余；
- 合同租金或付款金额为小数时，按分汇总，避免浮点误差；
- 付款附件缺失或已不可用时，显示“附件不可用”，其金额仍参与统计；
- 合同或收费记录在查询期间发生变化时，重新查询后反映最新数据，不保存静态对账快照；
- 租户名称存在历史写法差异时分为不同总账，第一版不提供手工合并，需先修正合同租户名称；
- 未找到租户或筛选结果为空时返回明确的空结果或 404，不暴露数据库错误。

## 测试与验收

后端测试覆盖：

- 无付款、部分付款、刚好结清和超额付款；
- 同一租户多份合同的累计汇总及每期归属；
- 租户名称首尾空格归一化和不同名称隔离；
- 年度筛选、状态筛选及组合筛选；
- 小数金额按分汇总；
- 软删除付款不参与统计、作废收据不作为有效收据返回；
- 空结果、租户不存在和 PDF 生成失败。

前端测试覆盖：

- 菜单和路由可访问；
- 总账字段、状态和金额格式正确；
- 筛选条件触发重新查询；
- 合同期间展开及实付明细展示；
- 付款附件和收据预览；
- 空状态、加载状态和接口错误提示；
- 打印及 PDF 下载使用当前筛选范围，且重复点击不会触发重复下载。

验收示例：租户“大理石”在 `2025-09-01` 至 `2026-08-31` 的合同应收为 `100000.00` 元。详情中完整列出该合同绑定的每笔实付，实收为这些付款之和，结欠或结余按上述公式显示；租户还有其他年度合同时，总账顶部同时显示筛选范围内的累计结果，各年度仍分别列明。
