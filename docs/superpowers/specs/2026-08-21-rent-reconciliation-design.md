# 房租对账设计

## 目标

新增独立的“房租对账”功能，帮助出租方按租户核对历年合同应收和实际收款。页面既能查看租户累计总账，也能展开到每一份合同租期和每一笔实付记录，并支持打印及下载 PDF 对账单。

本功能只汇总现有合同、房租收费、付款附件和收据数据，不增加应收账单表，也不改变现有房租收费流程。

## 对账口径

系统按合同中的 `tenantName` 归并租户。归并前去除名称首尾空格，名称完全一致的合同视为同一租户；名称不同的合同不自动合并，避免把不同主体误认为同一租户。

每份合同按租赁周年拆分为一个或多个对账期间：

- 第一个期间从合同 `startDate` 开始，后续期间从每个租赁周年日开始，期间结束日为下一周年日前一天或合同 `endDate`；
- 只计入截至查询当天已经开始的租赁期间，尚未开始的期间不提前形成应收；
- 每个已开始期间的应收金额取合同的 `annualRent`，最后不足一年的期间也不按天数折算；
- 同一合同下的有效房租收费记录按付款日期和记录编号升序，依次抵扣最早未结清的租赁期间；
- 单笔付款跨越多个期间时，按实际抵扣金额拆分显示在对应期间，附件、备注和有效收据随分配记录保留；
- 超出全部已开始期间应收的付款计入最后一个已开始期间的结余；
- 结欠金额为 `max(应收金额 - 实收金额, 0)`；
- 结余金额为 `max(实收金额 - 应收金额, 0)`。

租户累计总账为该租户全部纳入筛选范围的租赁期间汇总：

- 累计应收为各期间应收之和；
- 累计实收为各期间实收之和；
- 当前结欠和当前结余按筛选范围内各租赁期间的应收、实收重新计算；
- 状态分为“欠款”“已结清”“有结余”。

房租收费记录已经绑定 `contractId`，因此每笔实付只在所属合同的租赁期间内依次抵扣，不跨合同分配，也不按付款日期所在自然年推断归属。软删除的收费记录不参与统计。

## 页面入口与总账列表

左侧导航新增独立菜单“房租对账”，路由为 `/rent-reconciliation`。现有“房租收费”继续用于新增和管理收费流水，两个页面职责分开。

总账列表一行对应一个租户，显示：

- 租户名称；
- 租赁期间数量；
- 累计应收；
- 累计实收；
- 当前结欠；
- 当前结余；
- 最后付款日期；
- 对账状态。

页面支持按租户名称、租赁年度和对账状态筛选。租赁年度取拆分后期间的起始年份；付款先在完整合同内按 FIFO 分配，再按租赁年度筛选，避免筛选后改变付款归属。默认显示全部年度和全部状态。

金额统一保留两位小数。结欠为零时不显示欠款警示；结余为零时显示 `-`，避免把正常结清误解为超收。

## 租户对账详情

点击总账列表中的租户进入详情视图。顶部显示租户名称、筛选范围内的当前结欠和当前结余。

下方按租赁期间开始日期倒序显示。每个期间显示房源、租期、应收、实收、结欠、结余和状态，并可展开实付明细。每笔实付明细显示：

- 付款日期；
- 金额；
- 收款方式；
- 备注；
- 付款附件；
- 有效收据。

付款附件沿用现有图片预览能力。有效收据可直接预览；作废收据不作为有效收据入口显示。没有实付记录的租赁期间显示明确空状态，仍保留完整应收和结欠金额。

## 后端接口与数据流

新增独立的房租对账模块和只读接口，后端负责查询合同、有效房租收费记录及其有效收据，并完成全部金额汇总。接口返回租户汇总、租赁期间汇总和付款明细所需的稳定 DTO，前端不重复实现财务计算。

列表接口支持租户关键词、租赁年度和状态筛选。详情接口使用 URL 编码后的规范化租户名称定位同名合同，并接受相同的年度筛选。接口应复用现有鉴权、文件访问和收据预览方式，不返回文件系统路径或内部异常信息。

为避免 SQL `numeric`、JavaScript 浮点数和 PDF 输出之间产生分差，金额计算以“分”为单位汇总，响应时再转换为两位小数金额。

第一版数据量较小，可由后端一次查询相关合同、付款和收据后在服务层归并。接口必须避免逐租户或逐付款查询造成 N+1 查询；后续数据量增长时可以在不改变响应 DTO 的情况下替换为数据库聚合。

## 打印与 PDF

租户详情提供“打印”和“下载 PDF”两个操作。输出范围跟随当前租赁年度筛选，内容包括：

- 标题“房租对账单”；
- 租户名称和生成日期；
- 当前结欠和当前结余；
- 各租赁期间的房源、租期和金额汇总；
- 各期间的逐笔实付日期、金额、方式、备注和有效收据编号。

PDF 中当前结欠或租赁期间结欠不为零时，“结欠”文字及对应金额使用红色标注。付款图片不嵌入 PDF 正文，避免文件过大；页面仍可预览原附件。打印和 PDF 使用同一份后端汇总结果及同一套对账内容，确保数字一致。PDF 文件名为 `房租对账单_租户名称_YYYY-MM-DD.pdf`，并对文件名中的非法字符进行清理。

PDF 生成失败时页面保留当前对账数据并提示重新下载，不影响查询和打印。租户没有符合筛选条件的合同时禁用打印与下载操作。

## 错误与边界处理

- 同一合同没有付款时，实收为零，结欠等于应收；
- 跨年度合同时，每个已开始的租赁年度分别形成应收，未来租赁年度不提前计费；
- 最后不足一年的租赁期间仍按一次年租金计费，不按天折算；
- 部分付款时，展示所有实付并计算剩余结欠；
- 付款按最早未结清租赁期间依次抵扣，跨期付款拆分显示；
- 超额付款时，最后一个已开始期间结欠为零并明确显示结余；
- 合同租金或付款金额为小数时，按分汇总，避免浮点误差；
- 付款附件缺失或已不可用时，显示“附件不可用”，其金额仍参与统计；
- 合同或收费记录在查询期间发生变化时，重新查询后反映最新数据，不保存静态对账快照；
- 租户名称存在历史写法差异时分为不同总账，第一版不提供手工合并，需先修正合同租户名称；
- 未找到租户或筛选结果为空时返回明确的空结果或 404，不暴露数据库错误。

## 测试与验收

后端测试覆盖：

- 无付款、部分付款、刚好结清和超额付款；
- 同一租户多份合同的累计汇总、跨年度合同拆分及每期归属；
- 租户名称首尾空格归一化和不同名称隔离；
- 租赁年度筛选、状态筛选及组合筛选；
- 小数金额按分汇总；
- 软删除付款不参与统计、作废收据不作为有效收据返回；
- 空结果、租户不存在和 PDF 生成失败。

前端测试覆盖：

- 菜单和路由可访问；
- 总账字段、状态和金额格式正确；
- 筛选条件触发重新查询；
- 租赁期间展开及实付明细展示；
- 付款附件和收据预览；
- 空状态、加载状态和接口错误提示；
- 打印及 PDF 下载使用当前筛选范围，且重复点击不会触发重复下载。

验收示例：租户“王长建”在 `2024-10-08` 至 `2026-10-07` 的合同年租金为 `90000.00` 元。截至 `2026-08-26` 已开始两个租赁年度，应拆分为 `2024-10-08` 至 `2025-10-07` 和 `2025-10-08` 至 `2026-10-07` 两期，累计应收为 `180000.00` 元。若实收 `100000.00` 元，第一期实收 `90000.00` 元并结清，第二期实收 `10000.00` 元、结欠 `80000.00` 元。

完成后运行后端单元测试、前端单元测试、lint 和 build。推送后等待 GitHub Actions 镜像构建成功，再更新 DSM 项目并在线核对菜单、汇总、附件预览和 PDF 下载。
